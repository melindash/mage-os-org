Help build Mage-OS in a way that fits your skills and interests. You can fix a bug, improve a guide, test a feature, or help people understand what Mage-OS offers. Start with one small contribution and build from there.

## Choose your path

<ContributorPaths />

Before participating, read the [Code of Conduct](/code-of-conduct). Join [Discord](/discord-channel) to introduce yourself, find collaborators, or ask for help choosing a task. You can also participate through GitHub issues and discussions.

## Developers

**A good first contribution:** reproduce a small bug, add a regression test, and submit a focused fix.

1. Browse [open Mage-OS issues](https://github.com/mage-os/mageos-magento2/issues). Look for a `good first issue` label or a clearly described, limited change. If you cannot find a suitable issue, ask in Discord's technical discussion.
2. Read the issue and linked pull requests. Comment with your proposed approach and check whether someone is already working on it.
3. Follow the repository's setup and contribution instructions. Reproduce the reported behavior in a local development environment before changing the code.
4. Make a focused change and run the checks required by the repository. For a bug fix, add a test that demonstrates the failure and verifies the correction where practical.
5. Open a pull request against the branch specified by the project. Link the issue, explain the change, and include reproduction steps and test results. Respond to review comments in the same pull request.

**Useful resources:** [Developer contribution guide](/community/contributing), [core repository](https://github.com/mage-os/mageos-magento2), and [developer documentation](https://devdocs.mage-os.org/).

For a new module or a proposal to bundle an extension, read the [Module Acceptance Criteria and Process](/community/contributing/module-acceptance).

**Need help?** Share the issue link, the step you are stuck on, and what you have already tried in Discord's technical discussion. Remove credentials and private store data from logs and screenshots.

## Module authors

**A good first contribution:** describe one problem your module solves and discuss the idea with Mage-OS Lab maintainers.

1. Review the [Module Acceptance Criteria and Process](/community/contributing/module-acceptance), including maintenance, documentation, and licensing expectations.
2. Introduce your project in [Mage-OS Lab Discussions](https://github.com/orgs/mage-os-lab/discussions). Explain who it helps, what it does, and how you intend to maintain it. Link existing code if available.
3. Ask the maintainers for a repository in [Mage-OS Lab](https://github.com/mage-os-lab) when you need one. Repositories are currently created on request.
4. Develop the module and prepare the information needed for review. Follow the policy for acceptance, migration to the Mage-OS organization, or inclusion in an official release.

**Need help?** Use your proposal thread or ask for the Lab maintainers in Discord's technical discussion.

## Testers and merchants

**A good first contribution:** reproduce an existing issue or test one familiar workflow, such as creating a product or completing checkout, in a development or staging store.

1. Choose a reported issue or a feature described in the [release notes](/product/releases).
2. Record the Mage-OS version, relevant extensions, environment, and exact steps you followed.
3. Compare the expected and actual results. Add screenshots or a short recording when they explain the problem, with private information removed.
4. Add your findings to the existing issue. If the problem has not been reported, open an issue in the relevant repository with enough detail for someone else to reproduce it.

**Useful resources:** [Issue tracker](https://github.com/mage-os/mageos-magento2/issues), [developer documentation](https://devdocs.mage-os.org/), and [Discord](/discord-channel).

For suspected security vulnerabilities, follow the private reporting route on the [contact page](/contact) instead of posting details in a public issue.

**Need help?** Ask in Discord which version or scenario would be most useful to test. You can contribute a reproduction report without writing a fix.

## Documentation contributors

**A good first contribution:** follow a guide as a new reader, then fix one unclear step, outdated example, or broken link.

1. Choose a page in the [developer documentation](https://devdocs.mage-os.org/). Check that its instructions match the version you are using.
2. Find the source in the [documentation repository](https://github.com/mage-os/devdocs). Read its contribution instructions and use the appropriate branch for that version.
3. Submit a focused correction with a short explanation of the reader's problem. Verify commands and examples before including them.
4. If you are proposing a new tutorial or translation, discuss its scope in a repository issue before writing the full piece.

**Useful resources:** [Documentation contribution instructions](https://github.com/mage-os/devdocs#readme) and the [website repository](https://github.com/mage-os/mage-os-org) for changes to mage-os.org.

**Need help?** Open a documentation issue with the page link and suggested wording, or ask on Discord. You can report an unclear instruction without using Git.

## Marketing and design contributors

**A good first contribution:** offer to help with one short article, release announcement, event graphic, or explanation of a Mage-OS feature.

1. Introduce yourself on [Discord](/discord-channel) and ask to connect with the marketing team. Share your interests and the kind of task you would like to take on.
2. Agree on the audience, purpose, and reviewer before starting. Ask the team for the current approved brand assets, writing standards, and design guidelines.
3. Prepare a draft using those resources. Link the source for technical claims and ask a technical contributor to check details where needed.
4. Share the draft and editable files with the agreed reviewer. Coordinate publication through the marketing team for official Mage-OS channels.

**Useful resources:** the [Mage-OS FAQ](/faq) for project background, [release notes](/product/releases) for released features, and the [website repository](https://github.com/mage-os/mage-os-org) for website contributions.

**Need help?** Ask the marketing team for a small task and its approved reference materials. You do not need development experience to help with writing, design, or outreach.

## Community contributors

**A good first contribution:** help someone find the right guide or turn a support question into a clear problem report.

1. Join [Discord](/discord-channel) and choose a conversation where you can help.
2. Ask for the context you need, share relevant documentation, and be clear about what you have verified.
3. If a question reveals a documentation gap or possible bug, help the person find the appropriate repository and describe the problem.

**Useful resources:** [Code of Conduct](/code-of-conduct), [FAQ](/faq), and [developer documentation](https://devdocs.mage-os.org/).

**Need help choosing a path?** Tell the community what you enjoy doing and how much time you can offer. Start with a task small enough to finish, and ask questions as you go.
